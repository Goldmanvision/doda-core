  279: ## Deadzone aim authority
  280: 
  281: - `DoDA/Aim/AimInput.zs` owns raw mouse capture and dispatch only.
  282: - AimInput returns false while deadzone aim is inactive.
  283: - While deadzone aim is active, AimInput may consume mouse input and write only
  284:   established raw-input CVars such as `doda_raw_mouse_x` and
  285:   `doda_raw_mouse_y`.
  286: - AimInput does not own deadzone activation, smoothing, gap math, camera
  287:   handoff, HUD state, weapon state, reload behavior, or evidence behavior.
  288: - The active MAPINFO player class is the current authority for deadzone state
  289:   unless current active source proves otherwise.
  290: - For the current FieldAgent architecture, FieldAgent owns deadzone activation,
  291:   reset behavior, raw-input consumption, smoothing, yaw/pitch offsets, limits,
  292:   clamping, and overflow transfer to player angle/pitch.
  293: - HUD modules read deadzone state only.
  294: - HUD code must never own, modify, smooth, reset, clamp, or duplicate deadzone
  295:   math.
  296: - Weapon modules consume deadzone state for presentation, hand selection,
  297:   spread/trace behavior, and firing behavior.
  298: - Weapon code must not duplicate deadzone math or independently rewrite player
  299:   angle/pitch.
  300: - A visible HUD overlay is not proof that input capture, deadzone state, camera
  301:   handoff, weapon behavior, or trace behavior is correct.

  306: ## Lean authority
  307: 
  308: - Lean input owns Q/E button reading and edge detection only.
  309: - Lean controller owns lean direction, smoothing, applied lateral view offset,
  310:   and active lean-hand lock state.
  311: - HUD may read lean state/offset for presentation only.
  312: - Weapon code may consume lean output for sprite presentation, trace origin,
  313:   and permitted hand-lock routing only.
  314: - HUD must not own or mutate lean math.
  315: - Lean behavior requirements:
  316:   - Q held: left view translation and left-hand lock.
  317:   - E held: right view translation and right-hand lock.
  318:   - Q+E: no lean target and no hand lock.
  319:   - Release: smooth return to centered view and release hand lock.
  320:   - Lean lock has priority over manual pistol swap and deadzone threshold swap.
  321:   - V must not override lean hand lock.
  322:   - Camera roll is not part of the lean MVP.
  323: - Do not claim tactical lean is complete without human-run GZDoom evidence for
  324:   view translation, hand lock, V lockout, threshold restoration, HUD behavior,
  325:   and trace-origin behavior.
